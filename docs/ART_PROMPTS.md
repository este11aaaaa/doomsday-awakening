## 零之前、先搞清楚"要什么视角"（最重要的一节）

角色图只有三种可能，**先认准再出图**，否则画得再精致也用不了：

| 等级 | 视角 | 特征 | 能不能用 |
| --- | --- | --- | --- |
| ✅ 最优 | **正俯视 90°** | 只看到头顶发旋 + 双肩，看不到脸，人物被"压扁" | 旋转完美，首选 |
| 🟡 可用 | **斜俯视 60~75°**（含背后视角） | 能看到头顶和一点侧脸/后脑勺，人物略有厚度 | 旋转基本自然，AI 出得稳，**目前游戏里用的就是这种** |
| ❌ 不可用 | 站立全身正面/侧身 | 人物直立、脚在画面最下方、能看到完整脸 | 旋转 90° 就"躺下"，像纸片翻身 |

实测对照图：`docs/rotate-compare.png`（左：图1 斜俯视 ✅；右：图2 站立 ❌）
自检命令：`node tools/rotate-check.mjs 输出.png 你的图.png`

**所以：出图时要"斜上方俯拍、人物压扁"，不要"站立立绘"。**
如果模型始终给站立图，把第 1 条提示词开头换成：

```
俯视角游戏角色精灵图，从斜上方 65 度俯拍（top-down 3/4 view），人物被视角压扁、显得矮壮，
能看到头顶发旋、双肩与持枪双臂，几乎看不到正脸。镜头离人物约 4 米，人物占画面 80%。
角色朝向画面右侧，突击步枪从身体中线向右侧延伸。不要站立姿态，不要全身直立。
```

> 反向词务必补上：`站立姿势, 全身直立, 正面视角, 面部特写, 双脚站在地面, 侧视图`

## 九点五、实际出图记录（本项目已生成，可复用）

角色这 5 张是**用图生图（image-to-image）**跑出来的，这比纯文生图靠谱得多——因为参考图已经给出了正确的俯视构图。

### 有效配方

1. 先得到**一张**合格的俯视角色图（本项目是 `player.png`）。
2. 之后每个敌人：把 `player.png` 当 `image1` 参考图，写「保持同样的俯视相机与构图，但把士兵换成丧尸……」。
3. `input_fidelity`：
   - `high` → 构图、朝向最稳，但**会把参考图里的步枪带过去**；
   - `medium` → 更自由，适合「空手丧尸」这种需要**去掉**参考物件的场合。
4. 出图后一律跑：
   ```bash
   node tools/import-sprite.mjs raw/xxx.png characters/xxx.png      --anchor=0.5,0.5 --rotate=-90 --bright=1.15
   node tools/rotate-check.mjs docs/rotate-xxx.png characters/xxx.png
   ```
   `--rotate=-90` 是因为模型 80% 的会把朝向画成「朝下」；`--bright` 是因为 AI 图比程序化地板暗，不调会糊进阴影。

### 踩过的三个坑（都已在提示词里加了补丁）

| 坑 | 现象 | 补丁 |
| --- | --- | --- |
| **武器被继承** | 丧尸双手之间多出一根"枪/铁管"（其实是参考图里玩家的步枪） | `input_fidelity=medium` + 明确写 `双手完全空着、手指张开、手里什么都没有、不要枪/铁管/棍子` |
| **朝向朝下** | 出图后角色的头在画面下沿，进游戏像倒着走 | `--rotate=-90` 转成朝右；或提示词里写 `朝向画面右侧` |
| **太暗糊地** | 深色角色压在深色地砖上几乎看不见 | `--bright=1.1~1.2` 导出提亮 + 渲染时给一层地面微光 |

### 已生成的文件

`art-source/`：`player-source.png`、`zombie_normal-source.png`、`zombie_runner-source.png`、`zombie_spitter-source.png`、`boss-source.png`（+ `rejected/` 里存了一张被否掉的"站立立绘"样本）。
想重做某张，直接用上面的命令重新跑一次即可，渲染侧不用改代码。
